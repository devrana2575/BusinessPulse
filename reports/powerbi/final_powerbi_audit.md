- **COMPLETE** — Updated the page specification with the required KPIs and

- **COMPLETE** — Added detailed model contract and baseline, MySQL verification,
  metric reconciliation, and final audit reports.
- **COMPLETE (STATIC)** — Generated the PBIP/PBIR/TMDL project from embedded
  offline CSV snapshots: four pages, six tables, six relationships, 72
  measures, and 55 visuals. Static and saved-data consistency validation passed.
- **COMPLETE (STATIC)** — Validator now checks exact per-page visual inventory,
  catching stale report visuals rather than silently counting them as current.
- **COMPLETE (STATIC)** — Corrected TMDL generation to use documented `///`
  comments, the PBIP `database` declaration, nested table-object indentation,
  and explicit table, expression, and culture references. Static validation
  checks all 10 TMDL documents, declarations, references, and LF line endings.
- **COMPLETE (STATIC)** — TMDL documentation comments now directly precede
  their declarations; the validator rejects empty lines separating them,
  including the expressions-document failure reported during Desktop loading.
- **COMPLETE (GENERATOR FIX; DESKTOP PENDING)** — The error trace identifies
  `SingleColumnRelationship.ReadMetadataProperties`. The root cause was the
  generated `/// Generated by ...` header in `relationships.tmdl`: TMDL uses
  `///` to assign a description to the following object, so it implicitly
  assigned an unsupported description to the first relationship despite no
  literal `description:` property in the file. The generator no longer emits
  that header, and the static validator rejects `///` comments in the
  relationships document. This matches Microsoft's TMDL description syntax:
  https://learn.microsoft.com/en-us/analysis-services/tmdl/tmdl-overview?view=power-bi-premium-current#descriptions.
  Desktop validation is still required.
- **COMPLETE (STATIC)** — Fixed the subsequent Desktop error that
  `FactListings` had two columns with `IsKey = True`. The offline `listing_id`
  is an alias of `business_id`, not a separate key; it is now hidden, with
  `business_id` as the sole key column. Static validation checks each table's
  generated key-column declarations against its schema contract.
- **COMPLETE (GENERATOR FIX; OUTPUT REGENERATION PENDING)** — Corrected the
  generator to retain required PBIR `definition/report.json` metadata and
  remove only an empty Desktop-created legacy `BusinessPulse.Report/report.json`
  at the report-folder root. The prior cleanup incorrectly removed the
  required PBIR definition file, causing Desktop's subsequent “Cannot find
  file 'report.json'” error. Regeneration also removes recognized hidden
  auto-date TMDL documents, while preserving non-empty root reports and unknown
  table documents. Static validation requires the PBIR definition and rejects
  the conflicting root-level legacy file. Current output regeneration is
  pending.
- **PENDING (DESKTOP)** — Open/refresh validation, visual interactions,
  accessibility, genuine screenshots, and PBIX export.
